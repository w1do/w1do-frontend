AICRAFT — ИЛЛЮСТРАЦИИ И КОНТЕНТ ДЛЯ 120 НАПРАВЛЕНИЙ
Версия 1.0.0 · 27 ноября 2026

Этот комплект предназначен для секции «ИИ-агенты для вашей сферы» сразу после hero на главной странице. В нём есть графика для бегущих плашек и раскрытых карточек, тексты 120 сценариев, внутренние ссылки и исходники для редактирования.

Комплект готов к подключению в проект. Сайт AICraft этим комплектом не изменён и не развёрнут. Число 120 обозначает предложенные направления применения ИИ, а не количество реализованных кейсов или готовых внедрений.


1. КАК ПОСМОТРЕТЬ

1) Распакуйте архив целиком. Сохраните расположение папок относительно index.html.
2) Откройте index.html в браузере двойным щелчком. Это локальная галерея ассетов.
3) Для подключения в сайт используйте отдельные файлы и data/audiences.json.

Если браузер ограничивает чтение локальных файлов, откройте терминал в корне распакованного комплекта и выполните:

    python3 -m http.server 8000

Затем откройте http://localhost:8000/ . Сервер можно остановить сочетанием Ctrl+C. Для просмотра готовых SVG, PNG и WebP устанавливать Python или Node не требуется; Python нужен только для этого необязательного локального сервера и пересборки исходников.

Итого: 614 графических файлов, не считая обзорных изображений.

Названия файлов совпадают со slug направления. Например, карточке lawyers соответствуют illustrations/svg/lawyers.svg и icons/svg/lawyers.svg. Полные относительные пути для всех форматов находятся в audiences[].assets.


3. ВИЗУАЛЬНАЯ СИСТЕМА

Дизайн построен на 12 семействах композиций, по одному на тематическую группу. У всех 120 направлений есть собственная предметная иконка: весы, печать, калькулятор, мегафон, витрина, кран, швейная машина, грузовик и другие узнаваемые объекты.

Светло-синий стиль соединяет белые поверхности, тонкие линии, источники данных и результат работы агента. За пределами самой сцены фон прозрачен. Внутри иллюстраций могут быть белые и светло-синие поверхности. Иконки также имеют прозрачный фон.

В графику не встроены видимые заголовки, описания, кнопки или SEO-тексты. Их следует выводить настоящим HTML рядом с изображением. Служебные SVG-title — описания для доступности, а не видимые надписи.

Основная палитра из data/design-tokens.json:

    blue     #2563EB
    ink      #16336B
    pale     #EEF5FF
    line     #C5D8F5
    surface  #FFFFFF

SVG удобен для адаптивной вёрстки и редактирования. WebP предназначен для компактной растровой подачи на сайте. PNG пригодится там, где нужен более крупный растр с прозрачностью, например в презентации или редакторе.


4. ЧТО ЕСТЬ В МАНИФЕСТЕ

Источник данных — data/audiences.json. В массиве audiences находятся ровно 120 записей. Каждая содержит:

    label, slug                 Название и стабильный идентификатор.
    group_id, group_label       Принадлежность к одной из 12 групп.
    pain                        Конкретная проблема аудитории.
    workflow                    Три последовательных действия агента.
    outcome                     Ожидаемый результат сценария.
    example_process             Связное описание процесса.
    scene                       Предметный сюжет иллюстрации.
    alt                         Подготовленное описание изображения.
    assets                      Пути к SVG, PNG, WebP и иконкам.
    links                       Проверенные страницы связанных услуг.
    industry_page               Статус возможной отдельной страницы сферы.

Дополнительные разделы манифеста: section, interaction, seo, service_catalog, palette, formats, references. Дата проверки страниц услуг указана в services_verified_at.

Для кликабельной перелинковки используйте audiences[].links: объекты с title и href. Поле related_services сохраняет смысловые типы услуг из исходной подборки; это не готовые адреса и не обязательно ключи service_catalog.

Сценарии являются описанием возможного внедрения. Не оформляйте их как уже выполненные клиентские кейсы, гарантированную экономию или обещание полностью автономных профессиональных решений. Там, где требуется оценка специалиста, сохраняйте предусмотренную в тексте проверку человеком.


5. ПРИМЕР HTML

Ниже пример для случая, когда папки комплекта размещены на сайте в /assets/aicraft-audiences/. Если вы выбрали другой каталог, измените префикс пути.

    <article class="audience-card" aria-labelledby="lawyers-heading">
      <h3 id="lawyers-heading">
        <img src="/assets/aicraft-audiences/icons/svg/lawyers.svg"
             width="24" height="24" alt="" aria-hidden="true">
        ИИ-агент для юридической команды
      </h3>
      <img class="audience-illustration"
           src="/assets/aicraft-audiences/illustrations/svg/lawyers.svg"
           width="960" height="640" loading="lazy" decoding="async"
           alt="Сравнение договоров: документы с выделенными расхождениями.">
      <p>Агент сравнивает договор с шаблоном и готовит замечания для проверки юристом.</p>
      <a href="https://w1do.ru/ai-agents">Разработка ИИ-агентов</a>
    </article>

Для растровой версии замените src на illustrations/webp/lawyers.webp либо illustrations/png/lawyers.png. Сохраняйте соотношение сторон 3:2. У PNG исходный размер 1440 × 960; в HTML можно указать его исходные размеры, а отображаемую ширину ограничить CSS.

В карточках рядом с видимым названием иконка декоративная: alt="". У большой иллюстрации используйте audiences[].alt, если она добавляет смысл; если соседний текст полностью повторяет изображение, тоже допустим пустой alt.


6. ПРИМЕР REACT

Компонент получает объект из manifest.audiences. Данные можно импортировать на этапе сборки или подготовить на сервере; важные тексты и ссылки не должны существовать только после пользовательского клика.

    function AudienceCard({ audience: a, assetBase = "/assets/aicraft-audiences/" }) {
      return (
        <article className="audience-card">
          <h3>
            <img src={assetBase + a.assets.icon_svg}
                 width={24} height={24} alt="" aria-hidden="true" />
            {a.label}
          </h3>
          <img className="audience-illustration"
               src={assetBase + a.assets.illustration_webp}
               alt={a.alt} width={960} height={640}
               loading="lazy" decoding="async" />
          <p>{a.pain}</p>
          <ol>{a.workflow.map(step => <li key={step}>{step}</li>)}</ol>
          <p>{a.outcome}</p>
          <nav aria-label={`Услуги: ${a.label}`}>
            {a.links.map(link => (
              <a key={link.href} href={link.href}>{link.title}</a>
            ))}
          </nav>
        </article>
      );
    }

Пример CSS для окружающего интерфейса:

    :root {
      --aicraft-blue: #2563EB;
      --aicraft-ink: #16336B;
      --aicraft-pale: #EEF5FF;
      --aicraft-line: #C5D8F5;
    }
    .audience-card {
      color: var(--aicraft-ink);
      background: #fff;
      border: 1px solid var(--aicraft-line);
      border-radius: 24px;
      padding: 24px;
    }
    .audience-card h3 { display: flex; align-items: center; gap: 12px; }
    .audience-card a { color: var(--aicraft-blue); }
    .audience-illustration { display: block; width: 100%; height: auto; }
    .audience-card nav { display: flex; flex-wrap: wrap; gap: 16px; }

Точные токены лежат в data/design-tokens.json. CSS-переменные выше окрашивают интерфейс страницы. SVG, подключённый через <img>, не наследует цвет CSS от окружающего элемента. Для изменения самих ассетов меняйте палитру в исходнике сборки и пересобирайте SVG и растр; для встраиваемой inline-SVG-иконки можно переопределять color. При многократном inline-встраивании задавайте уникальные id/title и aria-labelledby либо оформляйте декоративные копии как aria-hidden.


7. ПОВЕДЕНИЕ БЕГУЩИХ СТРОК

• Четыре ряда: два верхних движутся влево, два нижних — вправо.
• При входе курсора в область ряда останавливается только этот ряд. Позиция не сбрасывается; после ухода движение продолжается с того же места.
• «Подробнее» проявляется внутри выбранной плашки без изменения её ширины. Место под надпись нужно предусмотреть заранее.
• Плашка — одна кнопка. «Подробнее» внутри неё не должно становиться вложенной кнопкой. Используйте aria-expanded и aria-controls.
• По нажатию открывается одна стабильная область с подробностями под рядами. Она не исчезает при уходе курсора. Выбор другой сферы меняет содержимое этой области. Закрытие — отдельной кнопкой или Escape.
• Фокус клавиатуры внутри ряда также ставит его на паузу. Enter/Space открывают карточку; после закрытия фокус возвращается на выбранную плашку.
• Поиск показывает неподвижную сетку результатов. Кнопка «Все 120 направлений» открывает доступный статичный каталог; её адрес следует назначить при создании такого каталога.
• На сенсорном экране используйте горизонтальный свайп и открытие одним нажатием. Не требуйте hover или второго тапа; автодвижение на таких экранах можно выключить.
• Добавьте общую кнопку паузы. Пользовательская пауза не отменяется после ухода курсора. При prefers-reduced-motion автодвижение изначально выключено.
• Копии элементов для бесшовной анимации не должны создавать повторные id или дополнительные таб-стопы. Нельзя прятать aria-hidden-копию, оставляя внутри неё доступные фокусу элементы. Видимый дубль должен открывать ту же карточку, не заводя фокус в скрытое дерево. Если эта механика усложняет компонент, используйте решение без интерактивных дублей.

Карточка раскрывает проблему, три действия агента, результат и 2–3 ссылки на связанные услуги. Кнопку обращения можно дополнить выбранным направлением, чтобы посетителю не пришлось повторно объяснять сферу.


8. РАЗМЕЩЕНИЕ ТЕКСТА И SEO

Секцию разместите сразу после hero. Используйте section.heading как H2, section.eyebrow — как небольшую поясняющую строку, section.intro — как видимый вводный абзац. Затем идут поиск, ряды направлений и область подробностей. Три абзаца section.seo_paragraphs можно разместить под рядами и карточкой в обычном текстовом блоке. Не превращайте их в текст на изображении.

Важные описания и ссылки должны быть доступны в обычной HTML-разметке, а не только в canvas, картинке или ответе на наведение. Для переходов используйте настоящие <a href> с названиями услуг. Копии элементов для анимации не должны раздувать индексируемый текст. Уникальные полезные страницы направлений можно публиковать постепенно по мере подготовки содержательного материала.

Предложенные пути вида /solutions/{slug}/ не подтверждены как существующие страницы. В industry_page.href стоит null, а suggested_path хранит только предложение для будущей архитектуры. Эти пути не включены в рабочий массив links. Не делайте из suggested_path кликабельные ссылки, пока соответствующие страницы не созданы и не проверены.

ИИ-агент полезен там, где команда регулярно обрабатывает сообщения, документы, заявки и данные. Для юридической практики это поиск по материалам и сравнение договоров, для маркетинга — подготовка контента и разбор отчётов, для продаж — обработка обращений и работа с CRM. В производстве, строительстве, образовании и сервисном бизнесе можно начать с одного повторяющегося процесса, у которого понятны входные данные и ожидаемый результат.

AICraft Agency проектирует автоматизацию под рабочий процесс компании. Подключаем агента к базе знаний, каталогу, внутренним документам и используемым системам. Он помогает найти нужную информацию, собрать данные клиента, подготовить документ, обновить статус заявки или передать задачу ответственному сотруднику. Для решений, требующих профессиональной оценки, предусматриваем проверку и согласование человеком.

В подборке представлены 120 направлений для внедрения. Откройте свою сферу: в карточке показаны типичная задача, сценарий работы агента и связанные услуги — разработка ИИ-агентов, чат-ботов, баз знаний RAG, автоматизация CRM и обработка документов. Если работа связана с внутренними данными, отдельно рассматриваем развёртывание локальных моделей. Начинаем с конкретной задачи и измеряем результат по согласованным показателям: времени обработки, числу ручных действий и качеству подготовленных материалов.


9. РЕДАКТИРОВАНИЕ И ПЕРЕСБОРКА

Для использования готовых файлов пересборка не нужна. Для изменения исходников потребуются Python 3, Node.js 18+ и пакет sharp. Выполняйте команды из корня комплекта:

    npm install sharp
    python3 source/build_assets.py
    node source/render_assets.cjs

build_assets.py формирует SVG и данные; render_assets.cjs экспортирует 120 PNG-иллюстраций, 120 WebP-иллюстраций и 120 PNG-иконок. Для правки текста используйте исходные данные в data/audiences-source.json, для сюжетов — data/visual-briefs.json, для предметных иконок — source/icons.json. Перед пересборкой сохраните свои изменения: сгенерированные файлы могут быть перезаписаны.

Палитра иллюстраций задана константами в source/build_assets.py. После её изменения пересоберите SVG и растр и согласуйте значения с data/design-tokens.json и CSS сайта. Эти исходники создают ассеты; они не подключают компонент в приложение и не публикуют сайт.
