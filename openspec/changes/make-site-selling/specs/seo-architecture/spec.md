# Spec Delta

## Purpose

Описывает структуру URL, полноту коммерческих страниц и внутреннюю перелинковку, от которых зависит видимость сайта в поиске.

## ADDED Requirements

### Requirement: Единая структура услуг

Сайт SHALL иметь одну иерархию страниц услуг. Страницы-дубли, конкурирующие за один поисковый интент, MUST быть объединены, а старые адреса MUST отдавать 301 на канонический URL.

#### Scenario: Старый адрес услуги открывается

- **WHEN** посетитель или робот открывает старый адрес услуги
- **THEN** он получает 301 на каноническую страницу той же услуги

#### Scenario: Дубль не индексируется

- **WHEN** поисковый робот обходит сайт
- **THEN** в sitemap и внутренних ссылках присутствует только канонический URL

### Requirement: Городские версии без дублей

Городские версии страниц SHALL отличаться содержанием: местными кейсами, контактами или условиями. Если уникального содержания нет, страница MUST быть закрыта от индексации или перенаправлена на общую.

#### Scenario: Городская страница уникальна

- **WHEN** робот сравнивает городскую и общую версии
- **THEN** городская содержит уникальный блок, которого нет в общей

#### Scenario: Дубль закрыт

- **WHEN** уникального содержания нет
- **THEN** страница отдаёт 301 на общую или содержит `noindex`

### Requirement: Коммерческая полнота страницы услуги

Страница услуги SHALL содержать цену, срок, состав работ, кейс, отзыв, FAQ, контакты и реквизиты. Страница MUST быть достаточной для принятия решения без перехода на другие разделы.

#### Scenario: Робот оценивает страницу услуги

- **WHEN** страница услуги отдаётся поисковому роботу
- **THEN** в HTML присутствуют цена, срок, состав, кейс, FAQ и контакты

#### Scenario: Посетитель принимает решение

- **WHEN** посетитель изучает услугу
- **THEN** он находит ответы на вопросы о цене, сроках и рисках на одной странице

### Requirement: Тематические кластеры и перелинковка

Каждая услуга SHALL иметь тематический кластер: хаб, 3–5 статей и перекрёстные ссылки. Статьи MUST ссылаться на услугу, а услуга MUST ссылаться на статьи кластера.

#### Scenario: Посетитель читает статью

- **WHEN** статья кластера открыта
- **THEN** в ней есть ссылка на соответствующую услугу и блок с призывом обсудить задачу

#### Scenario: Кластер связан двусторонне

- **WHEN** проверяющий открывает услугу
- **THEN** на ней есть ссылки на статьи кластера

### Requirement: Корректные структурированные данные

Страницы SHALL размещать schema.org разметку: `Service` с `Offer` для услуг, `FAQPage` при наличии FAQ, `BreadcrumbList` для навигации, `Article` для статей. Разметка `Review` и `AggregateRating` MUST использоваться только для проверяемых отзывов.

#### Scenario: Валидация разметки

- **WHEN** страница проверяется валидатором структурированных данных
- **THEN** обязательные поля заполнены и ошибок нет

#### Scenario: Рейтинг без отзывов не размечен

- **WHEN** на странице нет проверяемых отзывов
- **THEN** разметка `AggregateRating` отсутствует

### Requirement: Уникальные метаданные

Каждая индексируемая страница SHALL иметь уникальные title, description и canonical. Пагинация MUST иметь корректные canonical и ссылки предыдущей и следующей страницы.

#### Scenario: Проверка дублей метаданных

- **WHEN** проверяющий сравнивает title и description всех страниц из sitemap
- **THEN** дублей нет, а canonical указывает на саму страницу

#### Scenario: Пагинация блога

- **WHEN** робот открывает вторую страницу блога
- **THEN** canonical указывает на неё, а ссылки prev/next корректны
