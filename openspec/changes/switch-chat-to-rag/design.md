## Context

- Чат: `POST /api/chat` (`src/pages/api/chat.ts`) берёт состояние из Redis, строит промпт `buildSystemPrompt()` и вызывает `createPolzaCompletion()`. Метки `<lead>` и `<consent-request/>` разбирает `lead-directives.ts`.
- Знания сейчас: `buildKnowledge(await getServices())` в `src/lib/server/chat/system-prompt.ts`.
- Клиент: `AiChat.tsx` (варианты `page` и `widget`) + `useAiChat.ts`. `chatId` — `crypto.randomUUID()` на каждое монтирование.
- Источник заявки: `chat-request.ts` допускает только `chat-widget` и `chat-page`.
- Общий layout: `src/layouts/Layout.astro` (там же `CookieNotice`).

### Проверенный контракт RAG (Vector API 0.1.0, `http://localhost:8000/openapi.json`)

- `POST /api/v1/context`, заголовок `X-Api-Key`. Тело `ContextIn`: `project_id` (uuid, обязателен), `query` (1–2000 символов, обязателен), `max_chars` (200–50 000, по умолчанию 4000).
- Ответ `ContextOut`: `context` (string), `sources[]` (`source_id`, `title`, `version`), `warning` (string | null).
- `POST /api/v1/search` (`SearchIn`: `project_id`, `query`, `limit` 1–50) → `hits[]` с `text`, `score`, `title`, `locator`.
- `RAG_API_URL` в `.env` уже содержит префикс `/api/v1` (`https://rag.w1do.ru/api/v1`), поэтому путь — `${RAG_API_URL}/context`.
- Проверено запросом: ключ без нужного `project_id` → `403 {"detail":{"code":"forbidden",...}}`; с `RAG_PROJECT_ID` → `200`, фрагменты вида `[1] <title> (v1, score 0.03)\n<text>`.
- `search` возвращает фрагменты и на нерелевантные вопросы (например, «погода на марсе»), то есть «ничего не найдено» по пустому ответу определить нельзя.

## Decisions

### Решение 1: `/context`, а не `/search`

`/context` уже собирает фрагменты в один текст с лимитом `max_chars` и заголовками источников. Берём `max_chars: 4000`.
Альтернатива — `/search` и своя склейка. Отклонено: дублирует логику API.

### Решение 2: RAG + PolzaAI, модель отвечает только по контексту

RAG отдаёт фрагменты, а не ответ. Ответ пишет та же модель PolzaAI, но в промпте вместо каталога — раздел «Найденные сведения» с текстом `context`. Правила промпта: отвечать только по этому разделу; если там нет ответа на вопрос — сказать, что в базе знаний этого нет, и предложить заявку или `/contact`; не выдумывать цены, сроки, гарантии, кейсы, контакты и ссылки.
Так как RAG возвращает фрагменты и на посторонние вопросы, релевантность решает модель по правилу «нет ответа в разделе — не отвечай». Порог по `score` не вводим: шкала не задокументирована (`unverified`).

### Решение 3: запрос к RAG

`query` = последнее сообщение посетителя; если оно короче 40 символов, к нему через пробел добавляется предыдущее сообщение посетителя (уточнения вида «а сколько стоит?»). Обрезка до 2000 символов. Сообщение ассистента в запрос не идёт.
`fetch` с `AbortSignal.timeout(10_000)`, ключ только в заголовке `X-Api-Key`, ключ и URL не логируются (как в `polza/chat.ts`).

### Решение 4: RAG недоступен

`fetchRagContext()` возвращает `{ ok: false, reason: "config" | "auth" | "timeout" | "network" | "upstream" }`, а не бросает исключение. В этом случае промпт получает раздел «База знаний сейчас недоступна»: модель не отвечает по существу, дружелюбно извиняется и предлагает заявку. Сбор заявки продолжает работать.
Альтернатива — `503` на весь ход. Отклонено: посетитель потеряет возможность оставить заявку.

### Решение 5: ссылки

Модель даёт только ссылки, которые есть во фрагментах. Относительные пути из RAG (`/blog/...`) сервер не переписывает: в правилах промпта указано дописывать к ним `${SITE_ORIGIN}`. Плюс ссылка на форму `${SITE_ORIGIN}/contact`.

### Решение 6: плавающий ассистент — `ChatPopup.tsx`

Новый React-остров в `Layout.astro` (`client:idle`), не рендерится на `/chat`. Кнопка 56×56 внизу справа (`position: fixed`, над `CookieNotice` по `z-index`), по клику — панель 380×560 (на экранах ≤ 576px — на всю ширину и 85% высоты) с `AiChat variant="popup"`.
- Автооткрытие: при первом монтировании, если в `sessionStorage` нет `w1do-chat-popup` → открыть и записать `opened`. Закрытие записывает `closed`. Дальше окно открывается только кликом. Ошибки `sessionStorage` (приватный режим) → окно открыто, флаг не сохраняется.
- `AiChat` монтируется при первом открытии и не размонтируется при сворачивании, чтобы не терять диалог на странице.
- Доступность: `aria-expanded`, `aria-controls`, `Esc` закрывает, фокус переходит в поле ввода при открытии.
- Приветствие — статичный текст в клиенте, не запрос к модели: «Здравствуйте! Я ИИ-помощник W1DO DIGITAL. Спросите про наши услуги, цены или обучение — найду ответ в нашей базе знаний».

### Решение 7: источник заявки `chat-popup`

`ChatSource` расширяется значением `chat-popup`; `readChatTurn`/`chat-request.ts` принимает его. `submitLead` принимает любой непустой `source` (`asText(input.source) || "site"`), контракт `/api/lead` не меняется.

### Решение 8: удаляется каталог из промпта

Из `system-prompt.ts` уходят `buildKnowledge`, `appendWithinBudget`, `NO_CATALOGUE` и импорт `getServices`. `toPlainText` удаляется, если после правки не используется (проверить `grep`).

## Risks / Trade-offs

- Модель всё ещё может ошибиться в релевантности → температура 0.3 сохраняется, правило «только по разделу» стоит первым, тест на промпт проверяет наличие правила.
- Prompt injection через содержимое RAG → раздел помечается как данные, а не инструкции; правило 6 (не менять роль) распространяется и на него.
- Две независимые сессии чата на странице с `Cta` (встроенный + плавающий) → принято пользователем («оставить оба»).
- Секреты: в рабочей копии `.env.example` сейчас лежат реальные значения ключей (незакоммиченная правка). Их нужно вернуть к заглушкам и не коммитить; ключи, которые уже могли попасть в историю, — перевыпустить.

## Risk Score

45 — внешний API и смена промпта на пользовательском потоке, PII-логика не меняется, секреты только на сервере.
