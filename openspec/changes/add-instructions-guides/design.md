## Context

Проект — Astro 6 (SSR через `@astrojs/node`, `prerender = false` на контентных страницах). Контент из W1DO читается серверными адаптерами в `src/lib/server/w1do/*` (примеры: `opensource.ts`, `cases.ts`, `blog.ts`) через `GET /api/v1/content/...` с заголовком `X-Api-Key` и `locale=ru`. Коллекции W1DO имеют поля с `is_filterable`; в `cases` уже есть пара «select-рубрика + slug» (`category`, `category_slug`). Публичный HTTP-эндпоинт entries (`/api/v1/content/collections/<slug>/entries`) в существующем коде используется только с параметрами `locale`, `per_page`, `page` — поддержка серверной фильтрации полей через него не подтверждена.

В CMS сейчас нет коллекции `guides` и рубрик вида «туннелирование», «настройка Claude Code». Мотивация — в proposal.md, требования поведения — в specs/instructions/spec.md.

## Goals / Non-Goals

**Goals:**

- Коллекция `guides` в W1DO с рубриками и первые записи (структура → наполнение → публикация).
- SSR-раздел `/instructions` (индекс, рубрика, гайд) на существующем API, без новых эндпоинтов.
- Пункт «Инструкции» в шапке, включение маршрутов в sitemap.
- Файлы ≤150 строк, вёрстка в стиле существующих карточек блога.

**Non-Goals:**

- Новые API, клиентский SPA, поиск и пагинация внутри раздела (объём контента мал).
- Изменение блога, кейсов, OpenSource и их маршрутов.
- Наполнение всех гайдов — создаётся только структура и первые записи для проверки.

## Decisions

1. **Источник контента — новая коллекция `guides`, а не посты блога.**
   Посты жёстко привязаны к `/blog/...` (валидация URL в `mapPost`, канонические адреса в SEO), отдельный вид раздела из них не сделать. Коллекция даёт свои URL (`url_segment: instructions`), поля-рубрики и независимую эволюцию. Альтернатива «посты + новые категории» отклонена пользователем при выборе варианта.

2. **Структура полей коллекции — по образцу `cases`:** `title` (встроенное), `description` (textarea), `rubric` (select, `is_filterable`, примеры: «Как настроить Claude Code», «Туннелирование»), `rubric_slug` (text, `is_filterable`, латиницей: `claude-code`, `tunneling`), `cover` (image), `body` (rich_text), SEO-поля (`seo_title`, `seo_description` встроены у entries). Пара «label + slug» нужна, чтобы в URL не попадала кириллица, а в интерфейсе отображалось человекочитаемое название.

3. **Фильтрация по рубрике — на сервере, в памяти.** Адаптер выгружает все записи коллекции (постранично, как `getOpenSourceProjects`) и группирует их по `rubric_slug`; страница рубрики фильтрует массив. Альтернатива — параметр фильтра в HTTP-запросе: не подтверждён документацией и в проекте не используется, отклонён. Записей мало (десятки), стоимость пренебрежима.

4. **Маршруты** (`src/pages/instructions/`):
   - `index.astro` — все гайды + сайдбар;
   - `[rubric]/index.astro` — фильтр по рубрике, неизвестный slug → `Astro.rewrite("/404")` (как в `blog/categories/[...slug].astro`);
   - `[rubric]/[slug].astro` — полный гайд; slug не найден → 404; рубрика в URL не совпала с рубрикой записи → `Astro.redirect` 301 на канонический адрес.

5. **Адаптер `src/lib/server/w1do/guides.ts`** по образцу `opensource.ts`: `getGuides()` (все опубликованные записи, маппинг значений полей в тип `Guide`), `getGuideRubrics()` (уникальные рубрики из записей в порядке первой встречи), `getGuideBySlug(slug)`. Короткий module-level кэш (TTL ~60 с, как в `full-sitemap.ts`), чтобы страница не выгружала коллекцию дважды за рендер. Ответ API без `data` или коллекция 404 → пустой массив (пустое состояние, не 500).

6. **Компоненты** (`src/components/instructions/`, каждый < 150 строк):
   - `InstructionsSidebar.astro` — сайдбар рубрик (семантика `<nav>`, активная рубрика по `aria-current`), на мобильных — верхний блок над карточками;
   - `GuideCard.astro` — карточка по мотивам разметки `post-item` из `BlogList.astro` (обложка, заголовок, описание, стрелка), чтобы визуально раздел не выпадал из стиля сайта;
   - `GuidesGrid.astro` — сетка карточек (`col-xl-4 col-md-6`, как в блоге) и пустое состояние.

7. **Шапка:** в `src/components/shared/Header.astro` перед «Блог» добавляется `<li class="nav-item"><a class="nav-link" href="/instructions">Инструкции</a></li>` — тот же механизм, что у существующих пунктов.

8. **Sitemap:** в `src/lib/server/full-sitemap.ts` добавляются `/instructions`, адреса рубрик (все, где есть гайды) и адреса опубликованных гайдов; ссылки на коллекцию появляются в `Promise.all` рядом с `getCases()`/`getOpenSourceProjects()`.

9. **CMS-часть — отдельной волной, через MCP W1DO,** после «да» пользователя: `collections_create` (slug `guides`, `url_segment instructions`) → `fields_create` → наполнение → `entries_publish`. Публикация — отдельным действием; дубли исключаются `idempotency_key`.

10. **Хлебные крошки и SEO-метаданные.** На странице гайда — существующий `src/components/shared/Breadcrumbs.astro` (Главная → Инструкции → рубрика → заголовок). Title/description индекс-страницы и страницы рубрики задаются статически в `.astro`-файлах (для рубрики — из названия рубрики); у гайда — из `seo_title`/`seo_description` записи, canonical — собственный адрес страницы.

## Risks / Trade-offs

- [Не подтверждена фильтрация entries через HTTP] → фильтруем в памяти после полной выгрузки; при росте коллекции до тысяч записей ввести серверный кэш или подтверждённый параметр фильтра.
- [Пустой раздел до наполнения CMS] → пустое состояние на индексе (по образцу `/opensource`), пункт меню не убирается.
- [Кириллица в slug рубрики] → `rubric_slug` заполняется латиницей; адаптер отбрасывает записи без slug рубрики, чтобы не ломать маршруты.
- [Сборка файлов ≤150 строк] → логика разнесена по адаптеру и трём компонентам; страницы — только запрос данных и разметка-обёртка.
- [Ломающее изменение шапки затрагивает все страницы] → добавляется только новый пункт, порядок и вёрстка существующих не меняются; проверка — `npm run build` и визуальный просмотр.

## Migration Plan

1. Волна CMS (после «да» пользователя): создать коллекцию `guides`, поля, первые 2–3 записи, опубликовать.
2. Волна фронта: адаптер → компоненты → три страницы → пункт в шапке → sitemap.
3. Проверка: `npm run build`, dev-сервер — обход `/instructions`, `/instructions/<rubric>`, гайда, 404-кейсов, шапки на разных страницах.
4. Откат: убрать пункт меню и `src/pages/instructions/` — CMS-структура остаётся без влияния на сайт.

## Open Questions

Нет: источник контента (коллекция `guides`), базовый URL (`/instructions`) и объём (CMS + фронтенд) согласованы с пользователем.
