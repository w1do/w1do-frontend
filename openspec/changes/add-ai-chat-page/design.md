## Context

Полный план, сигнатуры и тексты лежат в `proposal.md`. Здесь собраны только решения и отвергнутые альтернативы.

- Astro 6, `output: 'server'`, `@astrojs/node` standalone, React 19 через `@astrojs/react`.
- Секреты читаются из `astro:env/server` (см. `add-platform-leads-api/design.md`, решение 2).
- Знания берутся из `getServices()` (`src/lib/server/w1do/services.ts`, кэш 60 с): хабы, споки и `faqs`.

## Decisions

### Решение 1: серверный роут `POST /api/chat`, ответ без стриминга

Браузер обращается только к собственному роуту, ключ PolzaAI живёт на сервере. Стриминг SSE отложен: при `max_tokens: 700` ожидание короткое, а без потока проще обработка ошибок, хук и роут.
Альтернативы: прямой вызов PolzaAI из браузера раскрывает ключ, отклонено. SSE в первой версии усложняет код без явной пользы, отложено.

### Решение 2: знания в системном промпте с бюджетом

Каталог услуг небольшой, поэтому RAG не нужен. Бюджеты: услуги до 7000 символов, FAQ до 5000; описание до 300 символов, ответ FAQ до 400, FAQ не больше 40. Строки добавляются по приоритету (хабы → споки; FAQ хабов → FAQ спок), пока следующая не превысит бюджет. Если W1DO недоступен, промпт собирается без каталога, и чат продолжает работать.
Альтернатива: векторный поиск. Для текущего объёма это лишняя инфраструктура.

### Решение 3: защита от злоупотреблений в памяти процесса

Сообщение до 1000 символов, история до 10 сообщений, тело до 32 000 символов. Окно 10 минут на 20 запросов с клиента и общий лимит 300 запросов в час. Ключ клиента — последний элемент `X-Forwarded-For`, иначе `clientAddress`. Контейнер один, поэтому хранения в памяти достаточно.
Альтернативы: Redis не нужен при одном инстансе. Капча мешает живому диалогу.

### Решение 4: заказ только через существующую форму

Промпт требует давать `https://w1do.ru/contact` и запрещает собирать персональные данные. Под чатом всегда есть ссылка на `/contact`. Сбор заявки в чате отклонён по решению пользователя.

### Решение 5: вывод ответа как текста

React экранирует ответ. Ссылками становятся только URL `https://w1do.ru/...`. Markdown не рендерится, поэтому HTML и чужие ссылки из ответа модели не исполняются.

### Решение 6: `/chat` индексируется (решение пользователя)

`robots="index, follow"`, запись `"/chat"` в `pageSeo` (`src/lib/seo.ts`) и путь `"/chat"` в массиве `paths` в `src/pages/sitemap-0.xml.ts`, как у остальных статических страниц. В индекс попадает статичная часть: заголовок, описание, приветствие и подсказки. Ответы модели генерируются на клиенте.

### Решение 7: модель задаётся через окружение

`POLZA_AI_MODEL` — серверный секрет со значением по умолчанию `openai/gpt-4o-mini` в схеме `astro.config.mjs` (выбор пользователя). В TS-коде ID модели нет. Сменить модель можно через окружение без деплоя кода.

Пустое значение `POLZA_AI_MODEL=` Astro считает незаданным и подставляет default; это установлено на T8b и принято при эскалации. Поэтому отдельной проверки модели в коде нет. Ошибка конфигурации (500) возникает только при отсутствующем `POLZA_AI_API_KEY`.

## Risks / Trade-offs

- **Лимиты в памяти** сбрасываются при рестарте и не делятся между инстансами. Если масштабироваться, нужен общий стор.
- **Подмена `X-Forwarded-For`** без обратного прокси обходит лимит по клиенту. Общий часовой лимит остаётся.
- **Доступность модели.** Пользователь выбрал `openai/gpt-4o-mini`. Researcher наличие этого ID в каталоге PolzaAI не проверял, его подтвердит smoke-тест T1. Если ID неверный, PolzaAI вернёт ошибку и посетитель увидит нейтральное сообщение; исправляется через `POLZA_AI_MODEL`.
- **Индексация приводит больше трафика на `/chat`.** Роботы JS не выполняют и `/api/chat` не вызывают. Расход ограничен общим лимитом 300 запросов в час.
- **Предположение об одном прокси.** Ключ клиента — последний элемент `X-Forwarded-For`. Ровно один обратный прокси перед контейнером проверяется пунктом чек-листа выкладки.
- **Текст диалога уходит в PolzaAI** как стороннему обработчику. Промпт просит не присылать персональные данные, но посетитель может их написать.
- **`drop_console: true` в terser** может убрать `console.error` из серверной сборки, как и у `/api/lead`. Это существующее поведение, не устраняется.
- **Модель может нарушить правила.** Prompt injection не исключается полностью, но в промпте нет секретов, а вывод безопасен.
